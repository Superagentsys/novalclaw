# 场景 4：单据识别与格式校验

> 预计耗时：5 分钟  
> 附件：自备 `发票样例.jpg`（清晰增值税发票截图/照片）  
> 依赖知识库：`单据字段模板-发票提单出入库.md`  
> **必须**使用支持视觉的模型

---

## 提示词 — 增值税发票

1. 上传发票图片
2. 发送：

```
请识别这张增值税发票，并按知识库「单据字段模板」抽取全部台账字段。

输出：
1. 结构化 JSON（含 invoice_code, invoice_number, issue_date, seller_name, seller_tax_id, buyer_name, buyer_tax_id, goods_name, amount_excl_tax, tax_amount, total_amount）
2. 格式校验结果：逐项 pass/fail，重点校验价税合计=金额+税额、税号18位
3. 校验失败的字段：生成推送给业务执行岗的问题清单
4. verification_status 设为 pending_official_check，注明待对接税务查验接口
5. 若全部格式校验通过，输出可写入智獴台账的 JSON，sync_status 设为 demo_only_not_submitted

不要声称已完成税务验真。
```

---

## 提示词 — 提单/出入库（可选加时 2 分钟）

上传提单或出入库单图片：

```
请识别本单据（提单或出入库单），按知识库字段模板抽取 JSON，并与业务单 BO-2026-DEMO 的合同数量 24000 吨做数量比对，标注是否在 ±5% 溢短装范围内。
```

---

## 预期输出示例（发票 JSON 结构）

```json
{
  "document_type": "invoice",
  "fields": {
    "invoice_number": "...",
    "issue_date": "2026-08-15",
    "seller_name": "...",
    "total_amount": 1800000.00
  },
  "validation": [
    { "rule": "total = amount + tax", "status": "pass" },
    { "rule": "seller_tax_id length", "status": "pass" }
  ],
  "verification_status": "pending_official_check",
  "verification_note": "待对接税务查验接口",
  "sync_status": "demo_only_not_submitted"
}
```

---

## 失败预案

| 情况 | 处理 |
|---|---|
| 模型无法读图 | 切换视觉模型；或口播「字段结构如下」并展示知识库 JSON 模板 |
| OCR 字段错误 | 强调「人工确认环节」；格式校验仍可通过 |
| 被问税务验真 | 答：「必须接增值税发票查验平台，AI 只做抽取和格式校验」 |

---

## 现场说明

- **口播**：「报关单 OCR 已在智獴上线；发票/提单/出入库走同一套字段映射流程。」
- **禁止说**：「已对接税务系统 / 银联验真 / 已同步财务系统」。
