# OmniNova 桌面端界面变更记录

## 2026-09-04：浏览器、知识库与 Office 交付修复

- 基于 `origin/testnew` 的 `dbe276c2` 更新。浏览器优先复用已安装的 Edge/Chrome（独立会话，不使用个人配置文件）；不自动关闭沙箱，不改变审批策略。页面加载超时后，仅在原地址正文已可读时返回带警告的部分结果，避免误报浏览器不可用。
- 分类新增改为应用内输入表单；空分类持久化，刷新/重启仍存在。重命名和删除直接更新元数据，不重写文档正文；default 为保留分类。
- 固定接入 AnyDoc 0.2.4（MIT），本地解析 DOC/DOCX、PPT/PPTX、XLS/XLSX、PDF、RTF、ODT。浏览器上传使用 Base64，单次最多 50 MB；桌面与 Gateway 共用解析器。Agent 的 file_read 同样支持文档正文分段读取，聊天附件限制内嵌预览长度。
- 加密文档需先解密，扫描文档仍需 OCR；不静默上传文档至外部转换服务。
- 修正 PPT 母版布局 ID 及四类主题样式列表的 Office 格式错误。默认正文采用开放式编号布局；保留显式 cards 与图文版式，长内容自动拆页，不再截掉后续要点。背景改用完整矩形，改善长标题与图片说明位置。
- Windows 文件定位去除 canonicalize 的 verbatim 前缀，正确传递 `/select,"路径"`，支持中文和带空格目录。
- 验证：前端生产构建、桌面 Rust 编译、知识库/Office 单测、独立浏览器真实开页与快照；原 PPT 经微软 Open XML 校验为 5 处错误，修复后样例为 0 处，并可由 PowerPoint 正常打开和导出 PNG。

升级说明：修复在源码中，安装中的 t0.1.4 不会自动变化，需要重新打包安装。旧的损坏 PPT 不会被后台改写，请重新生成。macOS 文档解析无需 Python/Node，浏览器仍需本机 Chrome/Edge 或通过浏览器设置安装 Chromium。

本文件用于记录 `zxy` 分支每次前端界面修改。后续新增页面、调整布局、修改主题或改变交互时，应在提交前补充一条记录，便于测试、验收与回退。

## 2026-08-21：工具权限策略与冲突配置修复

### 权限选择

- 任务输入区原“默认权限”按钮改为权限菜单，提供“请求批准”和“帮我批准”两种清晰模式，并显示各自适用范围。
- “请求批准”会在编辑文件、运行命令、Git 操作及访问互联网前要求确认；“帮我批准”会自动执行工作区内的常规操作，同时保留危险命令、禁止路径和工具安全策略。
- 权限切换直接写入本机配置并对新任务生效，保存过程、成功状态和失败原因均有明确反馈。
- “请求批准”不再把任务直接结束为英文错误，输入区上方会显示工具名称、命令、目标路径或网址，并提供“允许本次”和“拒绝”按钮；敏感参数会隐藏，完整参数可按需展开。
- 允许后继续执行原来的工具调用及原参数，不重新请求模型，不要求用户输入“再试一次”；每项批准只使用一次，后续受限操作会再次询问。
- 审批卡全部改用主题语义色，深色主题增加清晰边框、分层背景和内描边，避免面板与聊天背景融为一体。
- “允许本次”使用主题主色渐变及对比文字，“拒绝”使用中性按钮并在悬浮时显示危险色，同时补齐键盘焦点和禁用状态。

### 会话记忆

- 修复桌面流式任务只加载会话历史、成功后却没有保存新历史的问题；同一智能体后续发送“继续”“按刚才要求执行”等简短消息时，可以获得刚完成任务的上下文。
- 工具等待审批期间保持原任务和原提示词处于活动状态，避免权限切换后误用更早的对话内容生成无关结果。

### 配置一致性

- `[autonomy].auto_approve` 与 `[approvals]` 改由同一策略函数同步生成，受控工具不会再同时出现在“自动批准”和“必须批准”列表。
- 启动时自动识别旧版冲突配置；若旧配置已经把编辑、Shell、Git 或浏览器加入自动批准，则迁移为“帮我批准”，避免升级后继续出现 `tool execution requires user approval`。
- 英文审批错误改为中文操作提示，并提供“调整权限”快捷入口。

### 上游同步

- 本地 `zxy` 已快进到主分支 `v0.1.11.1`，保留最新技能运行时、合同审核工具和 Provider 诊断改进。

### 验证

- `cargo check -p omninova-core` 与 `cargo check -p omninova-tauri`：通过；仅有仓库原有警告。
