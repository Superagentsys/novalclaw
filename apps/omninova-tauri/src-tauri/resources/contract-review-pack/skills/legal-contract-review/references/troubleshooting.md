# 故障排查与降级

## 目录

1. 文本提取
2. 标注与修订
3. 报告与评分
4. 依赖与性能

## 1. 文本提取

- **格式不支持**：仅直接处理 PDF/DOCX；旧 `.doc` 或 WPS 文件先另存为 `.docx`。
- **扫描 PDF 为空**：安装 Tesseract 与中文语言包后重试 OCR；仍失败则请求电子版或清晰扫描件，并标出未审页。
- **乱码/缺字**：比较 pdfplumber 与 PyPDF2 提取结果；不要将乱码条款用于确定性判断。
- **加密文件**：请求合法密码或无密码副本；不得暴力破解。
- **表格缺失**：对照原件抽查金额、期限、责任与签署信息，必要时人工转录并标记来源。

## 2. 标注与修订

- PDF 不支持 Docx 标注脚本；改交定位清单或请求 Docx。
- Docx 标注后打不开或样式错乱时，先用 `annotate_contract_simple.py`，并只标高风险项；仍失败则交独立标注报告。
- 版本格式差异大时，文本行对比会误报。先核对提取文本，再人工确认实质性条款变化。
- 永不覆盖原合同；每次输出使用新文件名。

## 3. 报告与评分

- 报告截断：按章节单独重生成，再用 `merge_report_segments.py` 合并。
- 分段目录不存在：检查两位数字命名和 `.md` 文件是否位于 `segments/`。
- 评分异常：检查风险数量、合同类型、金额和合作对象参数；查看评分明细，但不为迎合预期手工调分。
- 高分不等于可直接签署；同时检查商业公平性、资料缺失和人工闸门。

## 4. 依赖与性能

- 缺模块：安装对应 Python 包；优先使用项目已有依赖环境，不擅自全局安装。
- OCR 慢：优先请求 Docx 或只 OCR 关键页，同时说明范围限制。
- 大文件慢：按章节处理并保留定位索引；不能通过只读开头来“提速”。
- 批量任务内存高：降低 `--workers`，逐份保存中间结果并汇总。

向用户报告问题时依次说明：发生了什么、影响哪些结论、已尝试什么、用户下一步可做什么。
