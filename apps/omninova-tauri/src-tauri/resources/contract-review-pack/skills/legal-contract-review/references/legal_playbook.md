## 概览

本手册用于指导智能体审查合同/标书中的法律风险点，识别不符合公司政策或存在法律风险的条款，并提供修改建议。

适用范围：
- 供应商合同
- 服务协议
- NDA（保密协议）
- 采购标书
- 其他商务合同

## 交易对手尽职调查

在审查合同条款之前，智能体应检查合同中是否包含以下关键主体信息。若缺失，应在报告中提示法务人员注意。

### 主体资格审查清单

审查合同时应检查以下信息是否完整：

| 审查项 | 必需程度 | 审查要点 |
|--------|---------|---------|
| **企业名称** | 必需 | 名称与营业执照完全一致，无错别字或简称 |
| **统一社会信用代码** | 必需 | 18位数字字母组合，格式正确 |
| **法定代表人** | 建议 | 法定代表人姓名与工商登记一致 |
| **注册地址** | 必需 | 完整地址，包括省市区 |
| **联系人及联系方式** | 必需 | 指定联系人姓名、电话、邮箱 |
| **开户银行信息** | 涉及付款时必需 | 开户名、账号、开户行完整 |
| **签约授权** | 建议 | 签约人是否具有合法授权（非法定代表人签约时需提供授权委托书） |

### 信用风险提示

**智能体审查时应注意**：
1. 本工具无法直接查询工商信息和信用记录，但应提示用户：
   - 通过国家企业信用信息公示系统核实对方主体状态
   - 通过中国执行信息公开网查询对方是否存在重大诉讼或失信记录
   - 优先使用企查查/天眼查等工具辅助调查
   - 重大合同建议要求对方提供营业执照、资质证书等文件

**风险信号**（合同文本层面可识别）：
- 对方名称与常用简称不符，疑似皮包公司
- 注册地址为虚拟地址或居民住宅
- 联系方式仅为手机号，缺少固定电话和企业邮箱
- 开户名与签约主体名称不一致

### 签约授权验证要点

- 非法定代表人签约时，应要求提供《授权委托书》原件
- 授权委托书应载明：授权人、被授权人、授权事项、授权期限
- 授权范围应覆盖合同签署事项
- 智能体应检查合同中是否注明了签约代表的职务和授权依据

## 审查原则

1. **风险导向**：优先识别高风险条款，确保不违反法律法规和公司政策
2. **平衡原则**：评估条款对双方权利义务的平衡性，避免明显不对等
3. **合规优先**：确保符合行业法规、反垄断法、反贿赂法等要求
4. **可操作性**：关注条款的清晰度和可执行性，避免模糊表述
5. **保护公司利益**：在合规前提下，最大化保护公司合法权益
6. **灵活适配**：根据合同类型、金额、合作对象等级调整审查策略

## 多维度评估规则

根据合同元数据进行多维度评估，调整审查策略和风险评分。

### 1. 合同类型

| 合同类型 | 审查重点 | 风险系数 | 特殊规则 |
|---------|---------|---------|---------|
| **NDA** | 保密义务、保密期限 | 0.8 | 保密期限一般不超过 3 年 |
| **服务合同** | 全面审查 | 1.0 | 标准审查流程 |
| **采购合同** | 质量保证、交付条款 | 0.9 | 重点审查质量标准和验收流程 |
| **合作协议** | 知识产权、违约责任 | 1.1 | 严格审查知识产权归属 |
| **其他** | 根据具体情况 | 1.0 | 智能判断审查重点 |

### 2. 行业专项规则

不同行业存在差异化法规要求，智能体应根据合同内容自动识别行业并加载对应规则。

| 行业 | 关键法规 | 专项审查要点 | 风险调整系数 |
|------|---------|-------------|------------|
| **金融** | 金融监管法规、反洗钱法 | 持牌经营条款、合规报告义务、反洗钱条款、数据报送要求 | 1.2 |
| **医疗健康** | 药品管理法、医疗器械管理条例 | 产品注册证/备案、不良反应报告、临床试验合规、广告宣传限制 | 1.2 |
| **互联网/科技** | 网络安全法、数据安全法、个人信息保护法 | 数据分类分级、用户同意机制、跨境数据传输、算法备案、未成年人保护 | 1.1 |
| **制造业** | 产品质量法、安全生产法、环境保护法 | 环保合规、安全生产责任、产品召回机制、供应链合规 | 1.1 |
| **房地产/建筑** | 建筑法、城市房地产管理法 | 资质要求、施工许可、验收标准、质量保证金 | 1.15 |
| **消费品/零售** | 消费者权益保护法、广告法 | 产品质量责任、退换货政策、广告合规、价格标示 | 1.0 |
| **能源/资源** | 能源法、矿产资源法、节约能源法 | 勘查/开采许可、安全生产、环境修复义务、碳排放 | 1.2 |
| **物流/运输** | 道路运输条例、安全生产法 | 运输许可、货物保险、承运人责任限制、危险品运输 | 1.1 |

**智能体使用规则**：
1. 审查时自动从合同标题、业务范围条款中识别行业
2. 根据行业加载对应的专项审查要点
3. 行业风险系数与合同类型系数、金额系数叠加使用

### 3. 合同金额（注：原编号2，现调整为3）

| 金额范围 | 审查级别 | 风险系数 | 审查要求 |
|---------|---------|---------|---------|
| **10 万以下** | 标准审查 | 1.0 | 按常规流程审查 |
| **10-100 万** | 加强审查 | 1.05 | 关注关键条款，详细说明 |
| **100-1000 万** | 严格审查 | 1.1 | 全面审查，提供详细分析 |
| **1000 万以上** | 最高级别审查 | 1.2 | 建议法务团队协同审查 |

### 4. 合作对象等级

| 合作对象等级 | 风险系数 | 审查策略 | 示例 |
|------------|---------|---------|------|
| **战略客户** | 0.8 | 审查标准适当放宽 | 长期合作伙伴，信任度高 |
| **优质客户** | 0.9 | 标准审查 | 有良好合作历史 |
| **标准客户** | 1.0 | 标准审查 | 首次合作或一般客户 |
| **基础客户** | 1.1 | 审查标准适当严格 | 新客户或风险较高的客户 |

### 4. 多维度评分计算

评分公式：
```
基础分 = 100
风险扣分 = 高风险数量 × 20 + 中风险数量 × 10 + 低风险数量 × 5
调整扣分 = 风险扣分 × 合同类型系数 × 金额系数 × 合作对象系数
最终得分 = max(0, 基础分 - 调整扣分)
```

风险等级判定：
- 0-59 分：高风险（不建议签署）
- 60-79 分：中风险（建议修改后签署）
- 80-89 分：低风险（可以签署）
- 90-100 分：无风险（推荐签署）

### 5. 审查策略调整

根据多维度评估结果，智能体应调整审查策略：

**高合同金额 + 基础客户**：
- 审查标准最严格
- 所有条款详细分析
- 提供多套修改方案
- 建议法务团队复审

**NDA + 战略客户**：
- 审查标准适当放宽
- 重点审查保密条款
- 其他条款简化处理
- 快速出具审查意见

**服务合同 + 标准客户**：
- 按标准流程审查
- 平衡审查速度和质量
- 提供清晰的修改建议

### 6. 使用建议

**智能体审查时**：
1. 首先收集合同元数据（类型、金额、合作对象等级）
2. 根据多维度规则选择适当的审查策略
3. 调整风险判定阈值（高风险客户的阈值更严格）
4. 计算综合风险评分
5. 在报告中说明多维度评估结果

**用户使用时**：
1. 提供合同元数据信息（可选）
2. 了解不同维度的风险影响
3. 根据风险评分决策是否签署
4. 参考调整后的审查建议

## 审查结论与审批建议

智能体在完成风险评估后，应给出明确的审查结论和审批建议，而非仅输出风险评分。

### 审查结论分级

| 结论 | 条件 | 操作建议 |
|------|------|---------|
| **推荐签署** | 评分 90-100，无高风险条款，中风险条款 ≤1 | 可直接进入签署流程 |
| **可以签署** | 评分 80-89，无高风险条款 | 签署前向法务负责人报备 |
| **附条件签署** | 评分 60-79，存在中风险条款但可接受 | 列出须修改条款清单，修改后签署；或法务负责人审批后签署 |
| **建议修改后签署** | 评分 30-59，存在高风险条款但可协商 | 必须先修改全部高风险条款，重新审查通过后方可签署 |
| **不建议签署** | 评分 0-29，存在多项重大法律风险 | 除非对方完全接受修改方案，否则不应签署 |

### 审批层级建议

根据合同风险等级和金额，建议以下审批流程：

| 风险等级 | 金额 | 建议审批层级 |
|---------|------|------------|
| 无风险/低风险 | 任意 | 法务专员审批 |
| 中风险 | 100万以下 | 法务主管审批 |
| 中风险 | 100万以上 | 法务总监审批 |
| 高风险 | 任意 | 法务总监 + 业务VP 联签 |
| 高风险 | 500万以上 | 法务总监 + 业务VP + CFO/CEO 联签 |

### 附条件通过的条件清单

当审查结论为"附条件签署"时，应在报告中列出明确的修改条件：

1. 必须修改的条件（不修改则不得签署）
2. 建议修改的条件（可在谈判中适当让步）
3. 可接受的现有条款（无需修改）

### 报告输出要求

审查报告"审查结论"章节必须包含：
- 综合风险评分及等级
- 审查结论（上述5类之一）
- 建议审批层级
- 附条件清单（如适用）
- 签署建议的有限期限（建议 15 个工作日内完成签署）

## 风险等级定义

### 高风险（必须修改）

定义：严重违反公司政策、法律法规或重大损害公司利益的条款。

判定标准：
- 违反反垄断法、反贿赂法等强制性法律规定
- 赔偿限额超过合同金额的 2 倍
- 知识产权归属不当，导致公司丧失核心资产
- 保密条款严重限制公司正常业务开展
- 适用法律为公司所在地以外的司法管辖区

处理要求：必须要求对方修改，否则不得签署。

### 中风险（建议修改）

定义：存在潜在法律风险或明显不合理的条款。

判定标准：
- 赔偿限额超过合同金额但未超过 2 倍
- 保密期限过长（超过 5 年）
- 违约责任不对等，对方责任过轻
- 解除条件过于苛刻
- 争议解决方式不利于公司

处理要求：建议协商修改，降低风险。

### 低风险（可考虑优化）

定义：表述不清晰、不完整或存在优化空间的条款。

判定标准：
- 条款表述模糊，可能产生歧义
- 缺少补充说明或细节
- 格式不规范，影响阅读
- 非核心条款存在小瑕疵

处理要求：可以要求优化，但不影响合同签署。

## 核心审查要点

### 赔偿限额条款

**审查规则**：

1. **限额标准**：赔偿限额不得超过合同总金额的 2 倍
   - 高风险：超过 2 倍
   - 中风险：超过 1 倍但未超过 2 倍
   - 低风险：低于或等于 1 倍

2. **除外责任**：检查是否存在故意行为、重大过失、侵权行为的例外
   - 应当明确除外情形不受限额限制

3. **责任覆盖**：确保覆盖所有可能的风险类型
   - 直接损失、间接损失、利润损失等

**常见问题**：
- 赔偿限额过高，远超合同金额
- 未区分责任类型，导致恶意行为也受限
- 未包含间接损失的赔偿

**修改建议**：
- 将赔偿限额调整为合同金额的 1-2 倍
- 明确故意、重大过失等行为不受限额限制
- 补充间接损失的赔偿条款

### 保密义务和期限

**审查规则**：

1. **保密期限**：一般不超过合同终止后 3 年
   - 高风险：超过 5 年
   - 中风险：超过 3 年但未超过 5 年
   - 低风险：3 年以内

2. **保密信息定义**：应当清晰界定保密信息范围
   - 明确包含商业秘密、技术信息、客户信息等
   - 列举具体类型，避免模糊表述

3. **豁免条款**：应当包含除外情形
   - 已公开信息
   - 第三方合法提供的信息
   - 法律法规要求披露的信息

4. **保密措施**：要求双方采取合理保密措施
   - 访问控制、加密存储、权限管理等

**常见问题**：
- 保密期限过长，超出合理范围
- 保密信息定义过于宽泛或模糊
- 缺少豁免条款，影响正常业务开展

**修改建议**：
- 将保密期限调整为 3 年以内
- 明确定义保密信息范围和具体类型
- 补充豁免条款和保密措施要求

### 知识产权归属

**审查规则**：

1. **现有知识产权**：双方各自拥有的知识产权保持不变
   - 明确保留各自在合同签署前已有的知识产权

2. **新增知识产权**：
   - 公司独立开发的，归公司所有
   - 对方独立开发的，归对方所有
   - 共同开发的，协商约定归属（建议公司享有优先使用权）

3. **知识产权授权**：
   - 对方应当授予公司必要的、非独占的、免费的许可
   - 许可范围应覆盖合同目的所需的所有使用方式

4. **侵权责任**：
   - 明确双方对各自知识产权的合法性负责
   - 约定侵权赔偿机制

**常见问题**：
- 知识产权归属不明确，存在争议风险
- 公司投入开发但知识产权归对方所有
- 缺少必要的知识产权授权

**修改建议**：
- 明确约定双方现有知识产权归属
- 合理分配新增知识产权归属，保护公司投入
- 补充知识产权授权条款

### 反贿赂和合规条款

**审查规则**：

1. **反贿赂条款**：必须包含反贿赂、反腐败声明
   - 双方承诺不进行任何形式的贿赂行为
   - 违反反贿赂条款视为严重违约

2. **合规义务**：要求遵守相关法律法规
   - 反垄断法、反不正当竞争法
   - 数据保护法、个人信息保护法
   - 行业监管要求

3. **监督机制**：约定合规监督和举报机制
   - 建立内部合规制度
   - 提供合规培训
   - 设立举报渠道

4. **违约后果**：明确违反合规条款的法律后果
   - 立即解除合同
   - 承担全部损失赔偿
   - 配合调查

**常见问题**：
- 完全缺失反贿赂条款
- 合规义务表述过于笼统
- 缺少监督机制和违约后果

**修改建议**：
- 补充完整的反贿赂和合规条款
- 列举适用的法律法规
- 明确监督机制和违约后果

### 解除条件和违约责任

**审查规则**：

1. **解除条件**：
   - 应当包含双方平等的解除权
   - 明确可解除的情形（重大违约、破产、不可抗力等）
   - 解除通知期限应当合理（一般 30 天）

2. **违约责任**：
   - 双方违约责任应当对等
   - 明确违约金的计算方式
   - 区分一般违约和重大违约

3. **整改机会**：给予违约方合理的整改机会
   - 一般违约：通知后 15-30 天内整改
   - 重大违约：可立即解除

**常见问题**：
- 解除条件过于苛刻，仅一方享有解除权
- 违约责任不对等，对方责任过轻
- 未给予整改机会，过于严厉

**修改建议**：
- 平衡双方的解除条件
- 调整违约责任，确保对等性
- 补充整改机会条款

### 适用法律和争议解决

**审查规则**：

1. **适用法律**：建议适用公司所在地或合同履行地的法律
   - 高风险：适用司法管辖区明显不公或难以执行
   - 中风险：适用非合同所在地但可接受的司法管辖区

2. **争议解决方式**：
   - 首选：协商解决
   - 其次：仲裁（明确仲裁机构，建议选择国内知名机构）
   - 最后：诉讼（建议明确管辖法院）

3. **费用承担**：约定争议解决费用的承担方式
   - 一般由败诉方承担
   - 或按仲裁裁决/法院判决

**常见问题**：
- 适用法律对公司明显不利
- 争议解决方式不明确或存在歧义
- 缺少费用承担约定

**修改建议**：
- 调整适用法律为双方可接受的司法管辖区
- 明确争议解决方式的具体程序和地点
- 补充费用承担条款

### 质量保证和交付条款

**审查规则**：

1. **质量标准**：明确产品/服务的质量要求
   - 符合国家标准、行业标准或双方约定的标准
   - 提供具体的验收标准和验收流程

2. **交付期限**：明确交付时间节点和方式
   - 分阶段交付的，明确各阶段时间
   - 延迟交付的违约责任

3. **质保期**：明确质保期限和质保范围
   - 一般质保期不少于 12 个月
   - 明确质保范围和响应时间

4. **服务水平协议（SLA）**（如适用）：
   - 明确服务可用性要求（如 99.5%）
   - 故障响应时间、恢复时间承诺
   - 服务中断的补偿机制

**常见问题**：
- 质量标准不明确，难以验收
- 交付期限模糊，缺少约束力
- 质保期过短或未明确
- 缺少 SLA（针对服务类合同）

**修改建议**：
- 明确具体的质量标准和验收流程
- 约定清晰的交付时间节点
- 合理设定质保期限和范围
- 补充 SLA 条款（服务类合同）

### 付款条款

**审查规则**：

1. **付款方式**：
   - 高风险：要求预付款比例过高（超过50%）且无担保措施
   - 中风险：预付款比例超过30%但不超过50%
   - 低风险：按进度分阶段付款，预付款比例合理
   - 对公转账优于现金或私人账户转账

2. **付款节点**：
   - 付款节点应与交付/验收节点绑定，不应无故前置
   - 建议采用"预付款+进度款+验收款+质保金"的分阶段支付结构
   - 质保金比例建议为合同金额的5%-10%

3. **发票要求**：
   - 明确发票类型（增值税专用发票/普通发票）、税率、开票时间
   - 约定先票后款或收到发票后N个工作日内付款

4. **逾期付款责任**：
   - 逾期付款的违约金应合理（一般日万分之三至五）
   - 违约金累计上限不超过合同金额的10%

**常见问题**：
- 要求100%预付款，公司承担全部风险
- 付款节点与交付脱钩，款项付清后对方履约意愿降低
- 缺少发票条款，导致财务处理困难

**修改建议**：
- 调整付款结构，绑定交付验收节点
- 补充发票条款和逾期责任
- 大额预付款要求对方提供履约保函

### 不可抗力条款

**审查规则**：

1. **定义范围**：应当明确列举不可抗力事件类型
   - 自然灾害：地震、洪水、台风、火灾、疫情等
   - 政府行为：征用、征收、法律法规变更、禁令等
   - 社会异常事件：战争、罢工、骚乱等

2. **通知义务**：
   - 受不可抗力影响的一方应在合理期限内书面通知对方
   - 建议通知期限为事件发生后7-15日内

3. **处理方式**：
   - 遭受不可抗力一方免除相应违约责任
   - 合同可中止履行，待事件消除后恢复
   - 不可抗力持续超过一定期限（如60-90天），任一方有权解除合同

4. **举证责任**：
   - 主张不可抗力的一方应提供相关证明材料
   - 如政府部门通知、媒体报道、公证文书等

**常见问题**：
- 缺少不可抗力条款或定义过于模糊
- 未约定通知期限和后续处理方式
- 不可抗力责任划分不明确

**修改建议**：
- 补充完整的不可抗力条款，明确事件类型和处理流程
- 约定通知期限和解除条件

### 通知送达条款

**审查规则**：

1. **送达地址**：
   - 双方应确认有效的法律文书送达地址
   - 包括通信地址、联系人、联系电话、电子邮箱等

2. **送达方式**：
   - 建议至少约定两种送达方式（如快递+电子邮件）
   - 明确视为送达的时间（如快递签收后第3个工作日）

3. **变更通知**：
   - 一方地址变更应及时书面通知对方
   - 未通知导致送达不能的，由未通知方承担不利后果

4. **法律效力**：
   - 明确该送达地址可作为司法文书的送达地址
   - 对后续争议解决和诉讼程序有重要影响

**常见问题**：
- 缺少通知送达条款或地址不完整
- 未约定视为送达的具体规则
- 电子送达缺少确认机制

**修改建议**：
- 补充完整的通知送达条款，确保双方信息完整
- 明确视为送达的规则和变更通知义务

### 合同期限与续约条款

**审查规则**：

1. **合同期限**：
   - 明确起止日期或生效条件
   - 附条件生效的，明确条件内容和判断标准

2. **续约机制**：
   - 自动续约条款属于中风险（容易遗忘导致被动续约）
   - 如果必须有自动续约，应约定提前通知期限（建议90天以上）
   - 推荐方式：到期前双方书面协商是否续约

3. **提前终止**：
   - 约定提前终止的条件和程序
   - 明确提前终止的违约金或补偿机制

**常见问题**：
- 自动续约条款容易导致被动续约
- 合同期限约定不明确
- 提前终止条件过于严苛

**修改建议**：
- 删除自动续约条款，改为到期协商续约
- 如保留自动续约，延长提前通知期限至90天以上
- 明确提前终止的条件和补偿机制

### 转让与分包条款

**审查规则**：

1. **合同转让**：
   - 一般约定任何一方未经对方书面同意不得转让合同权利义务
   - 确保转让需经过审批，保护公司选择合作方的权利

2. **分包管理**：
   - 允许分包时应明确主承包商对分包商行为承担连带责任
   - 要求分包商需具备相应资质
   - 关键部分不得分包

3. **控制权变更**：
   - 考虑增加控制权变更条款
   - 对方被收购或控制权变更时，公司有权终止合同

**常见问题**：
- 允许任意转包分包，缺乏约束
- 未约定主承包商对分包商的连带责任
- 缺少控制权变更保护

**修改建议**：
- 限制转让和分包，增加审批要求
- 明确连带责任，保护公司权益

### 数据保护与隐私条款

**审查规则**：

1. **法律依据**：必须符合《个人信息保护法》《数据安全法》《网络安全法》要求
   - 高风险：完全缺失数据保护条款
   - 中风险：条款不完整或未覆盖核心要求

2. **数据处理约定**：
   - 明确数据处理的目的是为履行合同所必需
   - 约定数据处理的范围、方式、期限
   - 禁止超出约定范围处理数据

3. **安全保护义务**：
   - 数据处理方应采取必要的安全保护措施
   - 包括加密存储、访问控制、安全审计等
   - 数据泄露事件的通知义务和时限

4. **跨境传输**：
   - 涉及数据出境需满足法定条件（安全评估、标准合同、认证等）
   - 明确跨境传输的合规责任方

5. **数据删除与返还**：
   - 合同终止后数据处理方应删除或返还所有数据
   - 明确删除/返还时限（建议30日内）

**常见问题**：
- 完全缺失数据保护条款
- 条款内容不符合最新法规要求
- 缺少数据泄露通知机制

**修改建议**：
- 补充完整的数据保护条款
- 引用具体法规依据
- 明确安全保护措施和违约责任

### 税务条款

**审查规则**：

1. **税费承担**：
   - 明确各项税费的承担主体
   - 合同价格为含税价还是不含税价
   - 增值税税率是否符合当前政策

2. **代扣代缴**：
   - 涉及境外供应商时需明确代扣代缴义务
   - 包括企业所得税、增值税及附加等

3. **发票管理**：
   - 开票时间和发票类型应当明确
   - 约定发票不合规的赔偿责任

4. **税率变动**：
   - 约定税率变动时的处理方式
   - 含税价不变还是不含税价不变

**常见问题**：
- 价格条款未明确是否含税
- 缺少发票管理条款
- 未处理税率变动场景

**修改建议**：
- 明确价格为含税价，注明税率
- 补充发票管理和税率变动条款

### 保险条款

**审查规则**：

1. **保险要求**：
   - 对方应购买并维持适当的保险
   - 常见保险类型：公众责任险、产品责任险、专业责任险、财产险

2. **保险金额**：
   - 保险金额应与合同风险匹配
   - 建议公众责任险不低于合同金额的2倍

3. **保险凭证**：
   - 要求对方在合同签署前提供保险凭证
   - 保险到期前应续保并提供新凭证

**常见问题**：
- 缺少保险条款要求
- 保险金额不足或险种不匹配

**修改建议**：
- 补充保险条款，要求对方提供保险凭证
- 明确保险金额和险种要求

### 终止后义务条款

**审查规则**：

1. **清算义务**：
   - 合同终止后应付未付款项的清算安排
   - 明确结算期限

2. **资料返还**：
   - 对方持有的公司资料、数据、文件应全部返还或销毁
   - 明确返还期限和方式

3. **存续条款**：
   - 某些条款在合同终止后继续有效
   - 包括保密义务、知识产权、争议解决等
   - 明确存续条款的清单和存续期限

4. **协助义务**：
   - 平稳过渡期间的协助义务
   - 对方应配合完成工作交接

**常见问题**：
- 缺少终止后义务条款
- 存续条款范围不明确
- 未约定资料返还义务

**修改建议**：
- 补充终止后义务条款
- 明确存续条款清单和期限
- 约定资料返还和协助义务

### 排他性条款

**审查规则**：

1. **排他范围**：
   - 审查排他性条款是否合理、是否对等
   - 排他性应符合商业合理性

2. **排他期限**：
   - 排他期限不宜过长
   - 建议不超过合同期限

3. **例外情形**：
   - 应当设定例外情形
   - 对方违约时排他性自动解除

4. **补偿机制**：
   - 排他性条款应有对等补偿
   - 如最低采购量承诺、价格优惠等

**常见问题**：
- 单方面排他，缺乏对等性
- 排他期限过长
- 缺少例外情形和补偿机制

**修改建议**：
- 争取对等的排他安排
- 设定合理期限和例外情形
- 增加排他性补偿机制

### 竞业限制条款

**审查规则**：

1. **适用对象**：
   - 竞业限制一般适用于劳动合同，但在合作协议、并购协议中也可能出现
   - 应明确适用的主体和范围

2. **限制范围**：
   - 竞业限制的地域范围应当合理
   - 竞业业务范围应当明确具体

3. **补偿机制**：
   - 竞业限制应有合理的经济补偿
   - 一般年补偿金不低于离职前年收入的30%（劳动法场景）

4. **期限和解除**：
   - 竞业限制期限一般不超过2年
   - 明确解除条件和程序

**常见问题**：
- 竞业限制范围过宽
- 缺少经济补偿或补偿不合理
- 期限超过法定限制

**修改建议**：
- 合理界定竞业限制范围和期限
- 确保有合理经济补偿
- 增加解除条件和程序

## 交叉引用一致性检查

### 检查要点

1. **定义术语一致性**：
   - 合同中首次定义的术语（如"甲方"、"乙方"、"合作项目"）在全文中应一致使用
   - 同一概念不应使用不同术语

2. **金额/数据一致性**：
   - 合同金额在正文和附件中保持一致
   - 金额的阿拉伯数字和大写汉字一致

3. **条款编号连续性**：
   - 条款编号应当连续，不应跳号或重复
   - 交叉引用的条款编号应当存在

4. **日期逻辑一致性**：
   - 签订日期不应晚于合同中约定的履行起始日期
   - 各阶段时间节点应当逻辑合理

5. **附件引用有效性**：
   - 正文中引用的附件应当实际存在
   - 附件名称和编号应与正文一致

**常见问题**：
- 条款编号混乱，交叉引用无效
- 金额前后不一致
- 定义术语在不同条款中使用不一致

**修改建议**：
- 逐项核对数据和编号一致性
- 统一术语使用
- 确保所有交叉引用有效

## 常见风险模式

**特征**：一方设定大量免责条款，另一方需承担无限责任。

**示例**：
- "供应商对因使用本产品导致的任何损失不承担责任"
- "甲方有权随时修改合同条款，乙方必须接受"

**风险等级**：高风险

**审查建议**：删除或修改单边免责条款，确保责任对等。

### 风险模式 2：自动续约条款

**特征**：合同到期后自动续约，缺乏明确通知机制。

**示例**：
- "合同到期后自动续约 1 年，除非一方提前 3 个月书面通知终止"

**风险等级**：中风险

**审查建议**：删除自动续约条款，改为到期前双方协商续约。

### 风险模式 3：管辖权不利条款

**特征**：选择对公司明显不利的司法管辖区。

**示例**：
- "本合同适用 X 国法律，争议提交 X 国法院解决"

**风险等级**：高风险（若 X 国司法环境对公司不利）

**审查建议**：选择对公司友好或中立的司法管辖区。

### 风险模式 4：模糊的违约金条款

**特征**：违约金计算方式不明确，容易产生争议。

**示例**：
- "违约方应赔偿守约方因此遭受的一切损失"
- "违约方应支付相应的违约金"

**风险等级**：低风险

**审查建议**：明确违约金的计算方式和上限，如"按合同总金额的 0.5%/天计算，累计不超过合同总金额的 10%"。

## 审查示例

### 示例 1：NDA 保密协议审查

**合同条款**：
> "双方应对在本协议履行过程中获知的对方所有信息承担永久保密义务。"

**审查分析**：
- 保密期限：永久（超过 5 年，高风险）
- 保密范围：所有信息（过于宽泛，中风险）
- 豁免条款：缺失（中风险）

**风险等级**：高风险

**修改建议**：
1. 将保密期限调整为 3 年
2. 明确保密信息范围为"商业秘密、技术资料、客户信息等"
3. 补充豁免条款："已公开信息、第三方合法提供的信息、法律法规要求披露的信息除外"

### 示例 2：服务合同赔偿条款审查

**合同条款**：
> "因甲方违约导致乙方损失的，甲方应承担全部赔偿责任，赔偿金额不设上限。"

**审查分析**：
- 赔偿限额：不设上限（超过合同金额 2 倍，高风险）
- 责任覆盖：全部损失（合理）
- 除外情形：缺失（中风险）

**风险等级**：高风险

**修改建议**：
1. 设定赔偿限额为合同金额的 2 倍
2. 补充除外情形："但因甲方故意或重大过失造成的损失不受此限"

### 示例 3：知识产权条款审查

**合同条款**：
> "双方在合作期间产生的所有知识产权归乙方所有。"

**审查分析**：
- 知识产权归属：全部归乙方（公司投入未获保护，高风险）
- 现有知识产权：未提及（中风险）
- 授权条款：缺失（中风险）

**风险等级**：高风险

**修改建议**：
1. 明确约定："双方在合作前各自拥有的知识产权归各自所有"
2. 调整新增知识产权归属："甲方独立开发的归甲方所有，乙方独立开发的归乙方所有，共同开发的由双方协商约定"
3. 补充授权条款："乙方应授予甲方使用其知识产权的必要许可，许可范围涵盖本合同履行所需"

## 批注生成格式

当需要在原合同文档中直接标注风险条款时，智能体应生成以下 JSON 格式的标注信息：

### JSON 格式定义

```json
{
  "input_file": "./合同.docx",
  "output_file": "./合同_已标注.docx",
  "annotations": [
    {
      "risk_level": "高风险|中风险|低风险",
      "category": "风险类别",
      "original_text": "原文片段（建议包含完整句子或条款）",
      "suggestion": "修改建议",
      "explanation": "风险说明（可选）"
    }
  ]
}
```

### 字段说明

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `input_file` | string | 是 | 输入文件路径（Docx 格式） |
| `output_file` | string | 是 | 输出文件路径（带批注的新文档） |
| `annotations` | array | 是 | 标注信息列表 |
| `risk_level` | string | 是 | 风险等级：高风险、中风险、低风险 |
| `category` | string | 是 | 风险类别（如：赔偿限额、保密义务等） |
| `original_text` | string | 是 | 原文片段，建议包含完整句子以提高匹配准确性 |
| `suggestion` | string | 是 | 修改建议 |
| `explanation` | string | 否 | 风险说明（可选，提供更多上下文信息） |

### 标注效果说明

- **高亮颜色**：
  - 高风险：黄色
  - 中风险：亮绿色
  - 低风险：灰色

- **批注格式**：
  - 在风险条款后添加批注标记
  - 批注内容：`[风险等级] 修改建议 (说明)`

### 使用批注功能的注意事项

1. **格式限制**：仅支持 Docx 格式，PDF 格式无法直接标注
2. **原文准确性**：`original_text` 应尽可能准确且包含完整句子，提高匹配成功率
3. **不覆盖原文**：标注功能会生成新的文档，不会覆盖原合同文档
4. **匹配精度**：使用模糊匹配，如果原文片段过长或存在差异，可能匹配到多个位置
5. **适用场景**：适用于需要向对方展示具体修改建议的场景，或内部评审时直观标记风险点

### 批注生成最佳实践

1. **提供准确的原文片段**：
   - 建议包含完整的句子或条款
   - 避免截断或省略关键词汇
   - 保持原文的措辞和标点符号

2. **明确的修改建议**：
   - 提供具体的修改内容，而非抽象的描述
   - 如："建议设定赔偿限额为合同金额的2倍"（好）vs "建议降低赔偿限额"（不够明确）

3. **合理的风险说明**：
   - 简洁说明风险原因，便于理解
   - 引用相关规则或标准（如"超过公司规定的2倍上限"）

4. **避免重复标注**：
   - 同一风险条款只需标注一次
   - 避免对相邻的句子重复标注
